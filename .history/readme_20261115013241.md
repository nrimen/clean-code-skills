# clean-code-skills

Five agent skills that help engineers, and the AI assistants coding with them, write clean code and check it afterwards.

- **Write it right:** `principles-first` and `solid-first` guide the assistant *while* it writes or changes code.
- **Check it:** `principles-audit`, `solid-audit` and `code-review` read your code *afterwards* and write a report with `file:line` evidence and concrete fixes.

Everything is read-only for your source code: the audits and the review never edit, commit or push. The only file they write is the report.

## What's inside

| Skill | Type | What it does |
|---|---|---|
| [`principles-first`](principles-first/SKILL.md) | Guide | Applies DRY, KISS, YAGNI, Single Responsibility and Separation of Concerns before and during any coding work |
| [`principles-audit`](principles-audit/SKILL.md) | Audit | Reports, for each of those 5 principles, whether the code respects it (✅ ⚠️ ❌ ➖) with evidence and fixes |
| [`solid-first`](solid-first/SKILL.md) | Guide | Applies the 5 SOLID principles when designing or changing structure: modules, interfaces, integrations, new variants |
| [`solid-audit`](solid-audit/SKILL.md) | Audit | Reports, for each SOLID principle, whether the design respects it, including "over-applied" abstractions |
| [`code-review`](code-review/SKILL.md) | Review | Reviews the current branch for bugs, security and quality; writes a severity-ranked report with a merge verdict |

## Which skill should I use?

| I want to… | Use |
|---|---|
| Have the assistant write simple, non-duplicated, well-layered code | `principles-first` |
| Have the assistant design a new module, service or integration cleanly | `solid-first` (plus `principles-first`) |
| Know if my code is DRY, simple, not over-engineered, well separated | `principles-audit` |
| Know if my design is extensible, testable and loosely coupled | `solid-audit` |
| Check my branch for bugs and risks before I push or merge | `code-review` |

A typical flow: the `-first` skills shape the code as it is written, the `-audit` skills check the design, and `code-review` gives the final pre-merge pass.

## The principles

**Principles skills** (`principles-first`, `principles-audit`)

| Principle | In one line |
|---|---|
| DRY | Don't repeat knowledge or logic |
| KISS | Keep it simple |
| YAGNI | Build only what the request needs |
| SRP | One reason to change per unit |
| SoC | Keep UI, business logic, data and config in separate layers |

**SOLID skills** (`solid-first`, `solid-audit`)

| Principle | In one line |
|---|---|
| S: Single Responsibility | One reason to change per module |
| O: Open/Closed | New variants mean adding code, not editing many places |
| L: Liskov Substitution | Every implementation honors its contract |
| I: Interface Segregation | Clients depend only on what they use |
| D: Dependency Inversion | Business logic depends on abstractions; infrastructure plugs in from outside |

Both families stay pragmatic: they include rules against over-applying the principles (no interface for a single implementation, no strategy pattern for one case), and they adapt to the language and paradigm in use.

## Install

### Claude Code

Copy the skill folders you want into your project's `.claude/skills/` folder (shared with your team) or into `~/.claude/skills/` (just for you):

```bash
git clone <repo-url> clean-code-skills
cp -r clean-code-skills/principles-first \
      clean-code-skills/principles-audit \
      clean-code-skills/solid-first \
      clean-code-skills/solid-audit \
      clean-code-skills/code-review \
      .claude/skills/
chmod +x .claude/skills/code-review/scripts/detect_context.sh
```

Each skill is self-contained, so you can install only the ones you need.

### Other tools

Any assistant that supports the `SKILL.md` format works the same way: copy the skill folders into its skills directory.

## Usage examples

```text
Add a "reset password" endpoint to the API.            → principles-first guides the code as it's written
Add Stripe as a new payment provider.                   → solid-first (new variant) + principles-first
Audit this branch against DRY, KISS and YAGNI.          → principles-audit
Is my code SOLID? Check the services folder.            → solid-audit
Review my branch, is it ready to merge?                 → code-review
```

The `-first` skills load automatically when the assistant is about to write or restructure code. The audits and the review run when you ask for them, on the scope you name; if you don't name one, they use the current branch compared with its base.

## Reports

| Skill | Report written to |
|---|---|
| `principles-audit` | `principles-audits/<scope>-<date>.md` |
| `solid-audit` | `solid-audits/<scope>-<date>.md` |
| `code-review` | `code-reviews/<branch>-<date>.md` |

Reports go to the repo root unless your project already has a reports folder. If you don't want them committed, add those folders to `.gitignore`.

**How to read them**

- Audits give a verdict per principle: ✅ respected, ⚠️ partially, ❌ not respected, ➖ not applicable. A finding marked `[blocking]` causes wrong behavior today, forces the next change to be made in several places, or makes the code untestable without editing it.
- `code-review` ranks findings 🔴 Critical, 🟠 Major, 🟡 Minor, ⚪ Nit, plus ❓ Questions, and ends with a verdict: ✅ Ready to merge, ⚠️ Merge after fixes, or ⛔ Not ready.
- Every finding points to a `file:line` and explains why it matters. No evidence, no finding.

## Good to know

- **Single Responsibility appears in both families.** If you run `principles-audit` and `solid-audit` on the same code, expect some overlap on SRP.
- **Some logic is duplicated between skills on purpose** (scope detection, verdict definitions). Each skill must work on its own when copied alone, so they don't share files.
- **`code-review` runs only the checks your project already defines** (lint, type check, tests), in check mode, and never installs dependencies or fixes files.
- **`code-review` has language notes** for JavaScript/TypeScript, Python, Go, Java/Kotlin, and shell, Docker, CI and infrastructure config. For other languages it uses the general checklist.
